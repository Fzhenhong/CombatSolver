## Q002 保存预测路线的严格验收（2026-10-03）

Testing新增通用保存预测部署与路径观察场景，按原生事件游标选择完整获胜预测，保留准确牌身份/选择，逐步对账增量与完整回放，通过原生入口执行。终局使用独立原生账本，常规后台搜索次数用跨战斗代次，避免结束清空造成假失败；生产搜索预算、评分和部署行为未改。O004的80动作实际完成T12/损血5、整场2瓶药、计划外重算合计0；短预算路径观察明确停在用药补搜预算门禁，不能声称搜索质量已修复。O005另补验原报告组合/药水奖励开关，同根同5秒诊断预算仍获胜战损22→8，总搜索耗时没有增加；原生自主搜索并完整执行也获胜战损8、无药/计划外重算0。证据和未验证范围见[Q002记录](issues/q002-route-quality.md#o004-完整预测可执行性与首个搜索缺口)。

## Q002 搜索政策开关导入（2026-10-03）

排查 O004 时确认检查点导入没有恢复 `useNoveltyPortfolio`、`useBeamWidthPortfolio`、`useEarlyTurnExploration` 和 `predictPotionReward`，显式 false 也会被本机当前设置替换。Testing 现在恢复已记录的四项开关，并允许显式政策覆盖及旧 settings 入口提供这些字段；未记录时维持既有兼容回退，不补造旧政策。普通游戏搜索实现和默认配置未改。

最小原生合同在修复前失败、修复后通过，验证真/假值、冻结政策和旧包回退；原 O004 start 的固定5秒请求确认正确执行新颖性开启、宽度组合关闭。目标仍只有未完成路线，玩家前缀后10秒诊断也未获胜；本轮完成测试导入修复，O004 路线质量未完成。此前 O005 的22→8双方执行政策相同，但组合/药水奖励开关与原报告不同，已修正验收口径，详见 [Q002 记录](issues/q002-route-quality.md#搜索政策开关恢复与-o004-后续诊断)。版本仍为0.48.0。

## Q002 O005 计算攻击估值（2026-10-03）

搜索的可用手牌、保留攻击和附魔重放价值统一使用已登记的分支 CalculatedDamage，修复基础 Damage 为空时计算攻击的状态变化与升级收益被忽略的问题。可用手牌同时计算额外重放；未登记模型沿用原估值，不调用 live delegate。不修改权重、预算、Beam、终局政策或战斗语义；尝试过的额外保路代表因质量退化全部撤回。

原始 O005 同一5秒成员预算下，原生完整战损22→8，无药水、计划外重算0。原生首回合完整状态、增量回放和冻结根合同通过；Body Slam+重放/升级/选牌的独立哨兵维持T1零损，原生完整部署和逐转移核验通过。玩家具体前缀仍可能被裁剪，改善来自实际搜索找到的另一条路线。最终数字、失败实验和范围见 [Q002 验收](issues/q002-route-quality.md#o005-分支攻击估值与原生验收)。其他四个主题未完成，版本保留0.48.0。

## Q002 O005 开局路径诊断（2026-10-03）

新增测试场景 `Q002-O005-OPENING-PATH`，只接受原包 T1 可出牌根。由原生 choice payload 解出 Burning Pact 的选择，在当前完整身份上重建玩家首回合，核对增量/完整回放，再原生执行 12 个录制事件并严格比较 T2 的完整 ContinuationStamp；不归一化差异。原生推进后另用新 worker 检查冻结根仍严格等于原 T1，随后使用推进前冻结的原根、战损账本、显示名和政策运行协调器。参照前缀只作为 SearchPathObserver 的观察目标，不注入搜索。纯值事件写入 EvidenceDirectory，实例清理后仍可排查；诊断不代表生产优化、完整路线或性能验收。

## Q002 检查点搜索 profile 恢复（2026-10-03）

O005 单因素实验发现覆盖文件记录 `CurrentEnergy:0`，实际政策却为默认值。导入器把 profile 转成玩家设置时只恢复基础容量和时间，丢弃排序、组合等字段。现在由请求内 `ProtocolHost` 持有完整不可变 profile，Runtime 冻结政策时消费它，显式 CLI 扰动继续优先；结束或失败后清除，普通请求沿原设置。该导入修复本身不调整生产搜索权重或战斗语义；后续路线优化见上节，过程与验证见 [Q002 排查](issues/q002-route-quality.md)。

## Windows 无头测试配置初始化（2026-10-03）

Windows 启动器补齐 Steam 账号配置向私有 `default/1` 的复制，修复只使用 Steam 配置的本机在游戏启动前报缺少 `settings.save` 的问题。保留已有 `default` 配置优先和隔离实例复用行为，沿用重解析点拒绝与来源只读复制。Windows/Linux 在多个可用 Steam 账号配置时均明确失败，避免静默选错账号。

独立配置选择测试通过；Windows 游戏 0.111.0、RitsuLib 0.6.5 上 `SMOKE-001` 通过，测试实例自动清理。该验证只覆盖测试入口和最小战斗，未验证社区问题包、完整回归、Linux 实机或性能。复用相同 C# 源码的成功 Release 构建和本地部署，未提升版本或发布。

## 下一版本（开发中）：巨斧机器人报告的重算偏差（2026-10-03）

从日志后台固定六份近期代表包，去重同场报告后定位三项当前语义偏差。金纸改为逐次记录并跨 Fork 保留延迟虚无消耗，覆盖异界嚎叫在回合末自动打出时，音乐盒新增复制牌的消耗；压缩按原版整批移除后的索引顺序插入燃料，原力与选牌变换继续逐张结算；回合末清理纳入只有临时星能费用的卡牌，修复子弹时间后 FOLLY 残留过期费用层导致重算。

三项失败基线和最终原生完整状态差分通过；原力/SEANCE 相邻调用哨兵及金纸根冻结、指纹/续用、父子和兄弟 Fork 合同通过。首轮倾泻排查停在录制恢复和中途导入障碍，未完成该项修复；后续改为直接注入倾泻前的有序牌堆和洗牌状态，复现了计划消耗痛击+、原生只有打击可选的同一异常。

倾泻选牌首因是无尽陀螺在模拟内层自动牌结束时提前抽牌。原版按玩家记录卡牌/药水效果的嵌套深度，在最外层效果结束、来源牌进入结果牌堆后才检查手空。引擎现在拥有相同的临时效果作用域；手动、自动、重复出牌与药水选牌均遵循该边界。选牌检查点保存每个执行步骤的不可变玩家身份序列，恢复时建立分支独占列表；普通 Fork 要求作用域为空。作用域只存在于动作事务和暂停帧中，稳定根与跨回合状态均为空，不新增状态键或续用字段。目标最小原生选牌、完整 continuation/RNG、完整回放与执行续接对账通过。

相邻验证 `EFFECT-SCOPE-ADJACENT-CONTRACT` 同请求通过三项手空边界、五种嵌套执行、手动自身选牌和九种药水的原生完整状态及检查点/Fork合同，包含兄弟/父根隔离、DOP2、重捕获和取消/异常后再访问。Release 编译零警告/错误，结构门禁通过。该修复阶段曾因证据状态枚举和原版模型重复构造未跑通 CoverageCatalog；后续工具修复与实际生成结果见下节。原生逐场完整部署、可见游戏与性能未验证；内存耗尽仍未修复，重生目标丢失与主线已有 B015 修复机制一致但未原包回放。具体报告、验证与边界见 [排查记录](issues/axebot-reports-20261003.md)。版本保留 0.48.0，未打包或发布渠道。
