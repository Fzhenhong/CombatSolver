# 偷窃策略的桶内损血剪枝

2026-10-04，适配基线 `9c9e975a1`，CombatSolver 0.49.1 / 游戏 0.111.0。第三层补丁在共享界与等值截断之上应用，见 [补丁档案](README.md)。

## 问题与证据

用户的 `THIEVING_HOPPER_WEAK-aaa1e06c03ca4876982dbaa43492b14b` 问题包日志显示：PreserveResources、零药胜利、首回合损血8，后续回合损血0，主搜与精炼的损血剪枝和更新计数均为0。读码确认两个入口直接在 PreserveResources 下返回：既不发布桶内胜利界，也不消费共享界。此次没有原生恢复该 ZIP；下面的实测来自最小固定夹具，不能称为原包完整回放。

另一个离线宿主问题是 `RunSearchDetailed` 固定传入 theftPolicy:null，偷牌遭遇没有采用生产策略。现在传入 `ResolveTheftPolicy(state)`，并让请求的 TheftPolicyForTest 在捕获搜索政策前生效。旧宿主的偷牌根结果需要重新核对政策字段，不能拿未启用保牌的对照验收此修复。

## 分桶与安全条件

- 沿用 `(最终未追回资源总量, 显式用药次数)` 的胜利表；资源量目前是金币数量加卡牌数量，没有按卡牌身份或价值细分。
- 完整胜利写入实际最终资源桶。PreserveResources 不消费没有资源类别的标量胜利界。
- 未终局节点按最终失窃量的乐观下界查询桶：当前失窃量减去仍由场上活着的怪物持有的可追回资源，最低为0。SwipePower、HeistPower、ThieveryPower 计入保守追回余量。
- 暂时被偷的牌仍可能被追回，因此不能直接拿当前失窃量查失牌桶；逃跑后资源才成为已确定的损失。没有下界对应桶的见证就保留节点。
- 保牌桶的胜利不会被失牌桶的较低战损覆盖。同一资源桶仍按既有损血下界裁剪；未来可能损失更多资源并不使其优于该桶的胜利。
- 药水档必须已经封闭，成长、遗物、风险、死亡保护及精确用药胜利资格继续受原门控约束。开放的药水档不使用当前档界限。
- 被 SwipePower 持有的 NotYet / Feed 也保留未来回血余量。不能因为它暂时离开手、抽、弃、消耗堆就判定再也无法回血。
- 等值截断沿用用户已授权的取舍：可能舍弃同资源损失、同战损但更早击杀的路线。不宣称保留原完整排序最优。

范围限于现有原版偷窃及回血政策；没有增加第三方内容支持或跨药水档支配。现有保牌策略会把未显式覆盖的有效药水政策设为 Smart；因此配置 Disabled 不必然令内层档封闭。本次目标对照使用与原包相同的 Smart 协调器，它显式运行禁药基线成员。
