## 根、分支和政策

Runtime 在稳定主线程根捕获资格与拒绝原因。监听者来自已有克隆前缀和已捕获全局成员，后台不读取实机牌组、药水槽或生命。资格随根冻结；Fork 使用原根的只读元数据，分支重新检查牌堆、待返回牌、Power 数量及显式用药记录。没有跨分支可变上界缓存，也没有新增战斗指纹字段。

Smart 仍使用原 `SmartRequiredHpSaved`、药水价值、替换奖励抵扣与首领规则。只有完整合规且未消耗保命资源的无药胜利提供基线。候选即使获得全部已证明回复，仍无法达到现有节血门槛时才剪枝；开局用药后续搜索通过既有请求传递同一基线，正常派发与审核流程继续执行。

新特化只用于精确用药层或开局用药后续搜索，要求根回复界为零且没有成长、遗物目标、强制用药和资源追回目标。未知分支保持原搜索。禁药、强制用药、资源追回、带骨肉目标、成长与复活资源的比较规则没有修改，也没有降低 Beam、节点、时间或并行预算。
